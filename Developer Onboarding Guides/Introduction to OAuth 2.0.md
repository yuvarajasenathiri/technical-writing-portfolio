# Introduction to OAuth 2.0

## What is OAuth 2.0?

OAuth 2.0 is an industry-standard protocol that lets you grant a third-party website or app (a client) delegated access to protected SmartHive resources through SmartHive APIs. It authenticates and 
authorizes API requests made to SmartHive.

## Advantages of OAuth 2.0

- Clients don’t need to support password authentication or store user credentials, because OAuth tokens handle authentication and authorization.
- Clients get delegated access only to the resources that the user authorizes.
- Users can revoke a third-party app’s delegated access at any time.
- OAuth access tokens expire after a set time. If a security breach affects a client, user data is at risk only while the access token is valid.

## OAuth 2.0 workflow

`Refer to the OAuth 2.0 glossary section to understand more about the terms used here.`

### Step 1: Register your app and get OAuth credentials

The first step in using OAuth authentication is to register your app with the SmartHive API Console. After you register your client, you receive a client ID and client secret for your application. 
The client ID and client secret authorize your app’s OAuth requests.

### Step 2: Obtain an access token

An access token is an OAuth token that you use to access protected SmartHive resources. How you generate the access token depends on the type of app. For example, server-based apps can use the authorization code 
flow, and client-based apps can use the implicit flow. In all cases, SmartHive provides an access token only after the user grants consent. Access tokens are always granted for the scopes specified in the request,
and SmartHive displays these scopes to the user when it asks for permission.

To learn about the workflows for each client type, see the following pages:

- Server-based apps
- Client-based apps
- Self client

### Step 3: Access the resource using the access token

After your app has the access token, it can access protected SmartHive resources. When your app gives the access token to the resource server, the server grants access based on the scopes defined in the request. 
SmartHive’s OAuth implementation uses the Bearer authentication scheme. When you make API calls, pass the access token in the `Authorization` header with the prefix `Bearer`.

Syntax: `Authorization: Bearer <space> {access-token-value}`
Example: `Authorization: Bearer 1000.2deaf8d0c2...`

### Step 4: Refresh the access token when it expires

An access token is valid for only 1 hour. After that, it expires, and you can’t use it to access resources. If your app needs access for more than 1 hour, retrieve and store a refresh token. Your app can 
use the refresh token to generate a new access token whenever it needs one.

### Step 5: Revoke unwanted tokens

If you no longer need a refresh token, or if you suspect that it’s compromised, you can revoke it by making an API request. After you revoke a refresh token, you can’t use it to generate access tokens, 
and any access tokens that were generated by using it become invalid.
